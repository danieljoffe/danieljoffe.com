<h1 className='doc-title'>Button</h1>
<p className='doc-lead'>
  Triggers actions. The primary interactive element across the system — use the
  right variant for the right context.
</p>

<h2 className='doc-section'>When to Use What</h2>

<p className='doc-p'>
  Buttons are the most common interactive element. Choosing the right variant
  prevents visual noise and maintains hierarchy.
</p>

<table className='doc-table'>
  <thead>
    <tr>
      <th>Variant</th>
      <th>Use when</th>
      <th>Example</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>
        <code>primary</code>
      </td>
      <td>The main call-to-action on a page. Limit to one per section.</td>
      <td>Submit form, Send message</td>
    </tr>
    <tr>
      <td>
        <code>secondary</code>
      </td>
      <td>
        A supporting action alongside a primary. Visually present but lower
        emphasis.
      </td>
      <td>Cancel, Back, Save draft</td>
    </tr>
    <tr>
      <td>
        <code>outline</code>
      </td>
      <td>
        Actions that need a clear boundary but not the weight of a filled
        button.
      </td>
      <td>Edit, Download, Export</td>
    </tr>
    <tr>
      <td>
        <code>bare</code>
      </td>
      <td>
        Custom-styled buttons where you want only the base interaction behavior.
      </td>
      <td>Icon buttons, custom UI chrome</td>
    </tr>
  </tbody>
</table>

<h3 className='doc-sub'>Need a variant we don't ship?</h3>

<p className='doc-p'>
  The four variants above are the complete set — <code>success</code>,{' '}
  <code>ghost</code>, and <code>danger</code> are <em>not</em> valid{' '}
  <code>variant</code> values (passing one renders an unstyled button). When you
  need a different look, extend <code>bare</code> — which is intentionally
  style-free — with utilities:
</p>

<div className='doc-grid'>
  <Button
    variant='bare'
    className='px-4 py-3 text-text-secondary hover:bg-surface-tertiary hover:text-text-primary'
  >
    Ghost (extended)
  </Button>
</div>

<p className='doc-p'>
  If a look is needed across the app, add it as a real variant upstream in a PR
  rather than repeating classes. See{' '}
  <a href='?path=/docs/guides-extend-don-t-reimplement--docs'>
    Extend, Don't Reimplement
  </a>
  .
</p>

<h2 className='doc-section'>Sizes</h2>

<p className='doc-p'>
  Choose size based on context, not personal preference. Dense UIs use{' '}
  <code>sm</code>. Page-level CTAs use <code>lg</code>. Default to{' '}
  <code>md</code> unless there's a reason not to.
</p>

<div className='doc-grid'>
  <Button size='sm'>Small</Button>
  <Button size='md'>Medium</Button>
  <Button size='lg'>Large</Button>
</div>

<h2 className='doc-section'>Loading State</h2>

<p className='doc-p'>
  Set <code>loading</code> to show an inline spinner and automatically disable
  the button. The button retains its label so the width stays stable — no layout
  shift. The spinner inherits the button's text color.
</p>

<div className='doc-grid'>
  <Button loading size='sm'>
    Saving
  </Button>
  <Button loading>Submitting…</Button>
  <Button loading size='lg'>
    Processing
  </Button>
</div>

<div className='doc-do-dont'>
  <div className='doc-do'>
    <div className='doc-do-label'>Do</div>
    <p className='doc-do-body'>
      Use <code>loading</code> for async operations. Keep the label descriptive
      so users know what's happening.
    </p>
  </div>
  <div className='doc-dont'>
    <div className='doc-dont-label'>Don't</div>
    <p className='doc-dont-body'>
      Don't replace button content with a standalone Spinner — the button width
      will jump and the user loses context.
    </p>
  </div>
</div>

<h2 className='doc-section'>Polymorphic Rendering</h2>

<p className='doc-p'>
  Pass <code>as="a"</code> to render the button as an anchor element. This is
  useful for navigation links that should look like buttons. All button styles
  are applied to the rendered element.
</p>

<div className='doc-grid'>
  <Button
    as='a'
    href='https://danieljoffe.com'
    target='_blank'
    rel='noopener noreferrer'
  >
    Visit Site
  </Button>
  <Button as='a' href='#' variant='outline'>
    Anchor Outline
  </Button>
</div>

<div className='doc-do-dont'>
  <div className='doc-do'>
    <div className='doc-do-label'>Do</div>
    <p className='doc-do-body'>
      Use <code>as="a"</code> for actual navigation. Add{' '}
      <code>rel="noopener noreferrer"</code> for external links with{' '}
      <code>target="_blank"</code>.
    </p>
  </div>
  <div className='doc-dont'>
    <div className='doc-dont-label'>Don't</div>
    <p className='doc-dont-body'>
      Don't use <code>as="a"</code> for actions that don't navigate — use a
      regular button. Anchors without <code>href</code> are semantically
      incorrect.
    </p>
  </div>
</div>

<h2 className='doc-section'>Accessibility</h2>

<p className='doc-p'>
  Every Button receives a visible focus ring via{' '}
  <code>focus-visible:ring-2</code>, offset from the background. Disabled
  buttons have <code>opacity-50</code> and
  <code>cursor-not-allowed</code>. Loading buttons set{' '}
  <code>aria-busy="true"</code> and hide the spinner from screen readers (the
  button's busy state conveys the message).
</p>

<div className='doc-do-dont'>
  <div className='doc-do'>
    <div className='doc-do-label'>Do</div>
    <p className='doc-do-body'>
      Add <code>aria-label</code> to icon-only buttons. Always provide visible
      text or an accessible name.
    </p>
  </div>
  <div className='doc-dont'>
    <div className='doc-dont-label'>Don't</div>
    <p className='doc-dont-body'>
      Don't rely on color alone to convey meaning. Pair semantic variants with
      clear labels ("Delete", "Approve") rather than just colored icons.
    </p>
  </div>
</div>
