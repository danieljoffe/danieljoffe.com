<h1 className='doc-title'>Input</h1>
<p className='doc-lead'>
  Single-line text field with built-in label, validation, and helper text.
  Handles the full lifecycle from empty to error without external wiring.
</p>

<h2 className='doc-section'>Anatomy</h2>

<p className='doc-p'>
  Input bundles four elements: a <code>label</code>, the <code>input</code>{' '}
  field, an <code>error</code> message, and a <code>helperText</code> hint. Each
  is optional and controlled via props — no wrapper components needed.
</p>

<div className='doc-example'>
  <Input label='Full Name' placeholder='Jane Doe' />
  <Input
    label='Email'
    placeholder='jane@example.com'
    helperText="We'll never share your email."
  />
  <Input
    label='Password'
    type='password'
    error='Password must be at least 8 characters.'
  />
  <Input label='Username' placeholder='jdoe' success />
</div>

<h2 className='doc-section'>States</h2>

<p className='doc-p'>
  Inputs move through four visual states. The component automatically wires ARIA
  attributes for each — <code>aria-invalid</code> for errors,
  <code>aria-describedby</code> linking to helper/error text, and
  <code>aria-required</code> when <code>required</code> is set.
</p>

<div className='doc-example'>
  <Input label='Default' placeholder='Type here...' />
  <Input
    label='With Helper'
    helperText='Helper text appears below the input.'
    placeholder='Type here...'
  />
  <Input label='Error State' error='This field is required.' />
  <Input label='Success State' defaultValue='Valid input' success />
</div>

<div className='doc-do-dont'>
  <div className='doc-do'>
    <div className='doc-do-label'>Do</div>
    <p className='doc-do-body'>
      Always provide a <code>label</code>. If the design requires a visually
      hidden label, use <code>aria-label</code> on the input instead.
    </p>
  </div>
  <div className='doc-dont'>
    <div className='doc-dont-label'>Don't</div>
    <p className='doc-dont-body'>
      Don't use <code>placeholder</code> as a substitute for <code>label</code>.
      Placeholders disappear on focus and fail WCAG.
    </p>
  </div>
</div>

<h2 className='doc-section'>Validation Patterns</h2>

<p className='doc-p'>
  Error messages are rendered as <code>role="alert"</code>, so screen readers
  announce them immediately. When both <code>error</code> and{' '}
  <code>helperText</code>
  are provided, the error takes precedence — helper text is hidden to avoid
  contradictory guidance.
</p>

<div className='doc-do-dont'>
  <div className='doc-do'>
    <div className='doc-do-label'>Do</div>
    <p className='doc-do-body'>
      Write error messages that tell the user how to fix the problem: "Password
      must be at least 8 characters" not "Invalid password."
    </p>
  </div>
  <div className='doc-dont'>
    <div className='doc-dont-label'>Don't</div>
    <p className='doc-dont-body'>
      Don't show errors on first render. Validate on blur or submit so the user
      has a chance to type before being told they're wrong.
    </p>
  </div>
</div>

<h2 className='doc-section'>Required Fields</h2>

<p className='doc-p'>
  Setting <code>required</code> renders a red asterisk after the label and adds
  <code>aria-required="true"</code> to the input. The native{' '}
  <code>required</code>
  attribute is also forwarded for browser-level validation.
</p>

<div className='doc-example'>
  <Input label='Email Address' required placeholder='jane@example.com' />
</div>

<h2 className='doc-section'>Accessibility Checklist</h2>

<div className='doc-do-dont'>
  <div className='doc-do'>
    <div className='doc-do-label'>Built in</div>
    <p className='doc-do-body'>
      Auto-generated <code>id</code> from label text. <code>htmlFor</code>{' '}
      linking.
      <code>aria-invalid</code> on error. <code>aria-describedby</code> pointing
      to helper/error text. <code>aria-required</code> on required fields.
    </p>
  </div>
  <div className='doc-dont'>
