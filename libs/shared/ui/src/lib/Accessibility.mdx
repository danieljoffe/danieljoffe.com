<h1 className='doc-title'>Accessibility</h1>
<p className='doc-lead'>
  Accessibility is a contract this library keeps so you don't re-implement it —
  usually incompletely. This page states the guarantees each interactive
  primitive makes, and, just as important, where the boundary is: the small set
  of things that are still your job. Trust the primitive over a hand-rolled{' '}
  <code>&lt;table&gt;</code> or <code>&lt;nav&gt;</code>; the accessibility
  you'd skip is the accessibility you'd ship broken.
</p>

<div className='doc-note'>
  <strong>These guarantees are enforced, not aspirational.</strong> Every story
  runs through <code>@storybook/addon-a11y</code> with{' '}
  <code>a11y: &#123; test: 'error' &#125;</code> — an axe violation fails the
  test run in CI. If a component's story is green, its rendered output passed
  automated checks.
</div>

<h2 className='doc-section'>Library-wide guarantees</h2>

<table className='doc-table'>
  <thead>
    <tr>
      <th>Concern</th>
      <th>What you get, everywhere</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Focus visibility</td>
      <td>
        Interactive elements render a <code>focus-visible</code> ring offset
        from the surface — keyboard focus is always visible, mouse focus stays
        quiet.
      </td>
    </tr>
    <tr>
      <td>Reduced motion</td>
      <td>
        Animations are gated behind <code>motion-reduce:</code> utilities, and
        the theme's base layer disables animation under{' '}
        <code>prefers-reduced-motion</code>.
      </td>
    </tr>
    <tr>
      <td>Contrast</td>
      <td>
        WCAG AA is the minimum bar. Text on brand uses the{' '}
        <code>text-on-brand</code> token (near-black or white per theme) rather
        than a hardcoded color that fails on one of them.
      </td>
    </tr>
    <tr>
      <td>Dark mode</td>
      <td>
        Every component is designed dark-first and verified in light — no
        low-contrast surprises when the theme flips.
      </td>
    </tr>
    <tr>
      <td>Keyboard</td>
      <td>
        Every interactive primitive is fully operable by keyboard; the
        per-component table below lists the specific keys.
      </td>
    </tr>
  </tbody>
</table>

<h2 className='doc-section'>Forms</h2>

<p className='doc-p'>
  Every control links its error node to the field via{' '}
  <code>aria-describedby</code>, sets <code>aria-invalid</code> when in error
  and <code>aria-required</code> when required, and renders the error with{' '}
  <code>role="alert"</code> so it's announced on appearance.
</p>

<table className='doc-table'>
  <thead>
    <tr>
      <th>Component</th>
      <th>Roles &amp; ARIA</th>
      <th>Notes</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>
        <code>Input</code> · <code>Textarea</code> · <code>Select</code>
      </td>

<h2 className='doc-section'>What you still own</h2>

<p className='doc-p'>
  The contract has edges. These are the places where the primitive stops and
  your app picks up — call them out so nobody assumes a guarantee that isn't
  there.
</p>

<div className='doc-do-dont'>
  <div className='doc-do'>
    <div className='doc-do-label'>Table sorting</div>
    <p className='doc-do-body'>
      Table renders semantic markup and keyboard-operable rows, but has{' '}
      <strong>no built-in column sorting</strong>. If you make columns sortable,
      you own the <code>aria-sort</code> on the <code>&lt;th&gt;</code> and the
      sort control. Don't hand-roll the whole table to add it — layer sorting on
      top.
    </p>
  </div>
  <div className='doc-dont'>
    <div className='doc-dont-label'>Skeleton is silent</div>
    <p className='doc-dont-body'>
      Skeleton is a visual placeholder with no ARIA of its own. Mark its
      container <code>aria-busy="true"</code> while loading, or{' '}
      <code>aria-hidden="true"</code> if it's purely decorative, so
      screen-reader users aren't left guessing.
    </p>
  </div>
</div>

<div className='doc-do-dont'>
  <div className='doc-do'>
    <div className='doc-do-label'>Standalone FormFieldError</div>
    <p className='doc-do-body'>
      Inside <code>Input</code>/<code>Select</code>/etc. the error is wrapped
      with <code>role="alert"</code> for you. If you render{' '}
      <code>FormFieldError</code> on its own, add <code>role="alert"</code>{' '}
      yourself so the message is announced.
    </p>
  </div>
  <div className='doc-dont'>
    <div className='doc-dont-label'>Icon-only buttons</div>
    <p className='doc-dont-body'>
      A Button with only an icon has no accessible name. Add an{' '}
      <code>aria-label</code> — the library can't infer one from an icon.
    </p>
  </div>
</div>
