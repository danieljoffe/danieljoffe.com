# Phase 2 Findings — Application code health (Next.js + Python)

**Run date:** 2026-05-04
**Branch:** audit/wyrdfold-pre-deploy
**Skills mirrored:** /nextjs-audit, /python-audit
**Scope:** apps/wyrdfold (Next.js 16.2.3), apps/wyrdfold-api + apps/audit-api (FastAPI / Python 3.11)

## Summary

15 findings total: 0 P0, 5 P1, 7 P2, 3 P3. No deploy blockers — both Python apps already pass `mypy strict` (verified: 113 + 18 source files clean), the Vercel cron is correctly auth-gated, and the `proxy.ts` middleware migration matches Next.js 16 conventions. Top concern is the wyrdfold-api unhandled-exception handler that returns the raw exception class + message to clients (information disclosure, finding 2.1). Other notable items: missing `global-error.tsx`, the dashboard page being a `'use client'` component (loses RSC streaming), and 22 `except Exception:` catches across wyrdfold-api services that mostly log but a handful silently swallow.

## Resolution status

13 findings resolved on this branch. **2.11 is a false positive** — `audit-api/Dockerfile:49` already runs `uv sync --frozen --no-dev --no-editable`. **2.9 and 2.13 deferred** as separate follow-up issues: 2.9 needs Pydantic response models that don't exist yet (creating ~20 of them mechanically risks shape drift) and 2.13 is a structural refactor (move shared types to a top-level barrel + update imports) that's better tracked as its own change.
