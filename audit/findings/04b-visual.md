# Phase 4b Findings — Visual / UX (authenticated app pages)

**Run date:** 2026-05-04
**Branch:** audit/wyrdfold-pre-deploy
**Skill mirrored:** /visual-audit
**Pages audited:** /dashboard, /onboarding, /jobs, /targets
**Tool used:** playwright MCP (chrome-devtools MCP not used; playwright remained primary as in 4a)
**Auth state:** authenticated for all 4 pages (Supabase cookie injection succeeded — `hello@danieljoffe.com`, real account data: 320 new matches, 4 targets, 17 pages of jobs)

## Summary

Audited 4 pages × 3 breakpoints (desktop 1440×900, tablet 768×1024, mobile 375×812) — 12 primary screenshots. Found **0 P0 / 3 P1 / 7 P2 / 4 P3** issues. Top concern: on mobile, the fixed bottom-tab nav (h=56px) overlaps page content because `<main>` has only `padding-bottom: 16px`. This breaks pagination on `/jobs` (the page-1 chip sits exactly under the nav and is half-obscured) and clips the 4th target card on `/targets`. Also: no contextual messaging exists on the path-chooser of `/onboarding`, and the `/dashboard` "Top matches" list has no per-row interactive affordance beyond the hyperlinked title.

**Pre-flight notes:**

- Dev server responded `200` on first attempt.
- Cookie injection via `document.cookie` worked first try. `/dashboard` rendered the full sidebar (Dashboard / Jobs / Targets / Profile / Insights / Settings + Sign out + theme toggle). `Page Title: Dashboard | WyrdFold`.
- Service worker cleared again at session start (carryover hygiene from 4a). Console errors during the run are 100% stale `apps/root/...` chunks from the prior danieljoffe.com session — not wyrdfold issues. Same finding as 4a; flagged for any 4c lighthouse run that needs a clean profile.

## Cross-page observations

- **Mobile bottom-nav clobbers content** (findings 11 + 18): the fixed bottom-tab nav (`<nav>` at h: 56px) overlaps the bottom of `<main>` on every authenticated mobile page. `<main>` only has `padding-bottom: 16px`. **Single layout-level fix** (e.g. `pb-20 md:pb-4` on `<main>` in the authenticated layout) resolves both P1 issues. This is the highest-leverage fix in the audit.
- **Score chip semantics drift across pages**: same chip component shows match-quality on /dashboard + /jobs and an unknown metric on /targets. Either unify (always = match score with consistent color tiers) or differentiate visually (different chip shape on /targets).
- **Theme toggle is invisible UI**: the monitor icon + "0" `<kbd>` in the bottom-left of the sidebar is unlabeled (visually) on every authenticated page. Audit affects /dashboard, /jobs, /targets, /onboarding (no sidebar there). Single fix in the sidebar component.
- **Tablet table layout is broken** (finding 12): /jobs is the only data-heavy table page audited but the same pattern likely repeats on a future /applications or /drafts table view. The 7-column table at 768px should switch to a card list at `md:` not just `sm:`.
- **No primary CTA pattern on /targets vs everywhere else**: /jobs has a clear filter row + table. /dashboard has a clear stat row + match list. /targets has a card grid with a floating FAB and a centered button — neither is a header CTA. Targets lacks a hero/header pattern.
- **Real account data renders cleanly**: 320 new matches, 4 targets, 17 pages × 20 jobs. No empty-state or zero-state issues. Data fetching works under the audit cookie.
