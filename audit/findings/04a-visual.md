# Phase 4a Findings — Visual / UX (public + entry pages)

**Run date:** 2026-05-04
**Branch:** audit/wyrdfold-pre-deploy
**Skill mirrored:** /visual-audit
**Pages audited:** /, /login, /dashboard
**Tool used:** playwright MCP (chrome-devtools MCP browser context died mid-session)

## Summary

Audited 3 pages × 3 breakpoints (desktop 1440×900, tablet 768×1024, mobile 375×812) — 9 screenshots total. Found **0 P0 / 2 P1 / 5 P2 / 4 P3** issues. Top concern: the `/login` email input renders a permanent 2px chartreuse box-shadow ring even when not focused, which both eliminates the visual distinction between focus / unfocused state (P1 a11y) and makes the disabled "Send magic link" button look like an error/disabled-rejection state. `/dashboard` could not be rendered as authenticated — observed the expected redirect to `/login?next=%2Fdashboard`; auth-wall fallback documented.

**Pre-flight notes:**

- Dev server responded `200` on first attempt (no compile wait needed).
- Playwright MCP browser context had a stale service worker (`http://localhost:3000/sw.js`) from a previous danieljoffe.com session that intercepted all navigations and served the old portfolio HTML. Unregistered the SW + cleared caches before audit. Logged finding so future audit runs can pre-empt this. (User memory `feedback_chrome_devtools_mcp_separate_cache.md` already covers this class of issue.)

## Cross-page observations

- **Header is inconsistent across routes**: landing page has `<header>` with logo + Sign-in CTA; login page has neither (just centered V-mark). Either commit to a global `<header>` in the public-route layout, or make the absence on /login explicitly intentional with a different hero.
- **Two different "primary CTA" sizes coexist on the landing page** (md hero, lg footer). Pick one for top-level conversion actions.
- **Disabled-button rendering pattern (50% opacity over chartreuse)** is reused on the disabled "Send magic link". If this pattern appears elsewhere in the dashboard (e.g. unsaved-form save buttons), it will look broken there too. Worth a single fix in the shared `Button` primary-disabled variant.
- **Footer is missing on /login** despite being present on /. Inconsistency at the lowest-friction page (login = highest conversion stake).

## Out-of-scope notes for Phase 4b/4c

- The hero image on the landing page (`/images/dashboard-screenshot.webp`) shows a fully-rendered dashboard with sidebar (WyrdFold | Dashboard | Jobs | Targets | Profile | Insights | Settings | Sign out). When auditing actual `/dashboard`, /jobs, /targets, etc. in 4b, compare against this asset to flag any drift between marketing promise and shipped UI.
- Sign-out CTA in the hero image is rendered as a full-width outlined button at the bottom of the sidebar. If the production sidebar uses the same pattern, verify it's not too prominent (sign-out shouldn't be a primary action).
- The hero image dimensions on desktop (1102×812) are large for an LCP image. `priority` is set in the Next/Image, but Phase 4c lighthouse should verify LCP under 2.5s at the desktop breakpoint.
- The proxy.ts middleware handles `/` → `/dashboard` redirect for authenticated users. Verify in 4b that the redirect chain doesn't add a perceptible delay on warm-cache returns.
- Console errors in playwright session are 100% stale SW artifacts from the previous danieljoffe.com dev server. Not a wyrdfold issue. Worth noting in 4b/4c that any subsequent audit runs should clear the playwright browser context (or reset its profile) before measuring.
