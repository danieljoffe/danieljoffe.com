## Summary

Audited 3 pages × 3 breakpoints (desktop 1440×900, tablet 768×1024, mobile 375×812) — 9 primary screenshots. Found **0 P0 / 3 P1 / 8 P2 / 4 P3** issues.

**Top concern:** the SMS "Phone number" input on `/settings` is missing `data-sentry-mask`. Combined with chart axis labels at `#666` (recharts default) on a dark theme failing WCAG AA contrast, and number inputs missing `min`/`max` HTML constraints despite advertising bounds in helper text, `/settings` + `/insights` are a P1 cluster.

**Brief vs. reality discrepancy (important):** the parent brief described `/profile` as a 6-PII-input form (name, email, location, phone, linkedin_url, website_url). The actual `/profile` is a Master Document editor — a single PII-bearing textarea + a file input. **Those 6 PII inputs live on `/settings`, not `/profile`.** The route layout is:

- `/profile` = Master experience document, Skills, Experience, Gaps to fill (read/edit narrative resume)
- `/settings` = Profile contact card (the 6 PII inputs) + Email notifications + SMS notifications

I audited both pages thoroughly, scoped PII-mask checks to `/settings` where the 6 inputs actually exist, and checked `/profile`'s single PII textarea separately.

**Pre-flight notes:**

- Cookie injection via `document.cookie` succeeded first try. `/dashboard` rendered the wyrdfold sidebar (Dashboard / Jobs / Targets / Profile / Insights / Settings + Sign out + theme toggle). Parent's strict "do not clear cookies" guidance was followed.
- Console errors during the run are minimal (0 errors at error-level on `/insights`). Stale `apps/root/...` chunks from prior session noted in 4a/4b are not present on these routes.
- Real account data renders cleanly: 2 applications, 1 interview, 50% response rate, $2.61 LLM cost, 52+ skills, 2 gaps, 5 experience entries.

## Cross-page observations

- **Mobile bottom-nav overlap pattern (4b finding #11/#18) does NOT recur on these 3 pages.** Each page's bottom-most content has built-in extra spacing — verified at `/profile` ("Answer 2 questions" CTA at y=688 vs nav at y=755 = 67px clearance), `/insights` ("Download Insights" at y=689 vs nav at y=755 = 66px clearance), and `/settings` (form ends well above the fold). **The `<main>` `padding-bottom: 16px` is still the same as 4b — but the layouts here don't push content into the danger zone.** 4b's recommended `pb-20` fix is still desirable as a layout-level safety net.
- **PII masking is mostly correct, with one gap:** 6/6 Profile-section inputs on `/settings` are properly masked, plus the master-document textarea on `/profile`. The single SMS-section phone input (finding #7) is the only PII surface lacking `data-sentry-mask`.
- **Numeric input bounds enforcement is non-existent at the HTML level** (finding #8). Helper text advertises "0-200", "1-50" but actual `<input type="number">` has no `min`/`max`/`step`. Server validation may catch this, but adding HTML attrs is free defense-in-depth.
- **Recharts theming wasn't customized for dark mode** (findings #15-#17). Default recharts axis fill is `#666` which is fine for light theme but fails AA on the dark surface. Charts also have no a11y labels. **Single fix at the chart-component-wrapper level resolves all three findings.**
- **Cross-tenant data leak on `/api/jobs/insights/*`** (Phase 2 finding, issue #645) — confirmed: visible insights data on this run is the authenticated user's own, but per Phase 2 the endpoints don't filter by user. Not re-flagged here per parent instruction.
- **Console is clean on these 3 pages** — 0 errors at error-level. Stale `apps/root` chunk noise from 4a/4b is not present on these routes.
